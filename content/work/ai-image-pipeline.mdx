## Decisions & trade-offs

### Stream uploads, answer with a job ID

Uploads are streamed instead of buffered, and the API returns a job ID immediately so the client never waits on processing.

### Preprocess in Worker Threads

Image preprocessing runs in Worker Threads so CPU-heavy work stays off the main event loop. [PLACEHOLDER: pool size and back-pressure]

### Retries and dead-letter queues before Model Serving

Failed jobs are retried, and jobs that keep failing go to a dead-letter queue instead of being lost. [PLACEHOLDER: retry policy and queue technology]

### Results over WebSocket

Clients receive results over WebSocket as soon as a job finishes. [PLACEHOLDER: reconnect and missed-message handling]
